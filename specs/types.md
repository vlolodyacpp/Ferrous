# Система типов языка Ferrous

Документ определяет все типы данных языка Ferrous, правила типизации,
нетипизированные литералы, составные типы, преобразования и управление
памятью.

---

## 1. Основные типы

| Тип        | Размер  | Описание                          |
| ---------- | ------- | --------------------------------- |
| `int8`     | 1 байт  | Знаковое целое, −128 … 127        |
| `int16`    | 2 байта | Знаковое целое, −32 768 … 32 767  |
| `int32`    | 4 байта | Знаковое целое (по умолчанию)     |
| `int64`    | 8 байт  | Знаковое целое                    |
| `uint8`    | 1 байт  | Беззнаковое целое, 0 … 255        |
| `uint16`   | 2 байта | Беззнаковое целое, 0 … 65 535     |
| `uint32`   | 4 байта | Беззнаковое целое                 |
| `uint64`   | 8 байт  | Беззнаковое целое                 |
| `float32`  | 4 байта | Вещественное, IEEE-754 single     |
| `float64`  | 8 байт  | Вещественное, IEEE-754 double     |
| `bool`     | 1 байт  | Булево значение (`true`/`false`)  |
| `string`   | —       | UTF-8 строка, неизменяемая        |
| `char`     | 4 байта | Unicode codepoint (UTF-32)        |
| `void`     | 0       | Отсутствие значения               |

### 1.1 Символьный тип `char`

Тип `char` представляет один Unicode-кодпоинт в UTF-32 (4 байта). Литерал
заключается в одинарные кавычки: `'a'`, `'Z'`, `'\n'`, `'\0'`.

Операции:
- `==`, `!=` — сравнение символов по коду.
- Преобразование через `as`:
  - `char as uint32` — получить кодпоинт;
  - `uint32 as char` — получить символ из кода; значение > 0x10FFFF —
    ошибка времени выполнения.

Арифметика над `char` запрещена. Для арифметики нужно явно
конвертировать в `uint32`, выполнить операцию, и при необходимости
вернуть в `char` через `as`.

### 1.2 Специальные значения float

`float32` и `float64` могут принимать специальные значения:
- `nan` — не-число (Not a Number). Результат `0.0 / 0.0`.
- `inf` — положительная бесконечность. Результат `1.0 / 0.0`.
- `-inf` — отрицательная бесконечность. Результат `-1.0 / 0.0`.

Литералы `nan` и `inf` являются нетипизированными float-литералами;
конкретный тип (`float32` или `float64`) определяется контекстом по
правилам §2.

Сравнения с `nan` следуют IEEE-754:
- `nan == X` → `false` для любого X (включая `nan == nan` → `false`);
- `nan != X` → `true` для любого X.

## 2. Нетипизированные числовые литералы

Числовой литерал без суффикса не получает фиксированный тип на этапе
лексического анализа. Его тип определяется семантическим анализатором в
точке использования по следующим правилам.

### 2.1 Контексты, задающие ожидаемый тип

- аннотация типа переменной: `let x: T = <lit>`;
- параметр не-перегружённой функции: `f(<lit>)`, где существует
  единственная `fn f(x: T, ...)`;
- тип возвращаемого значения: `return <lit>;` внутри функции с типом
  возврата `T`;
- тип поля структуры в литерале: `Point { x: <lit> }`;
- тип элемента литерала массива: `[<lit>, ...]` при известном типе
  массива `[T; N]`;
- противоположный операнд бинарного оператора, если он имеет
  фиксированный числовой тип.

### 2.2 Правила разрешения типа

1. Если в точке использования задан ожидаемый числовой тип и значение
   литерала укладывается в его диапазон — литерал получает этот тип.
2. Если ожидаемый тип не задан или не является числовым — применяется
   **тип по умолчанию**: `int32` для целых литералов, `float64` для
   вещественных.
3. Литерал с суффиксом имеет фиксированный тип и не подстраивается под
   контекст. Несоответствие суффикса ожидаемому типу — ошибка компиляции.
4. Нетипизированный литерал, значение которого не укладывается в
   ожидаемый тип — ошибка компиляции (`literal out of range for <T>`).

### 2.3 Распространение ожидаемого типа через бинарные операторы

Если один операнд — нетипизированный литерал, а другой имеет
фиксированный числовой тип `T`, литерал принимает тип `T`. Если оба
операнда — нетипизированные литералы, ожидаемый тип контекста применяется
к обоим; при отсутствии контекста применяется тип по умолчанию.

### 2.4 Примеры

```
let x: int8   = 5;              // 5 → int8 (из аннотации)
let y: uint32 = 0;              // 0 → uint32
let z: int64  = 100 + 200;      // оба литерала → int64
let a: int8   = 10;
let b: int8   = a + 1;          // 1 → int8 (другой операнд int8)
let k = 42;                     // контекста нет → int32 по умолчанию
let m = 42i64;                  // суффикс → int64
let err: int64 = 42i32;         // ОШИБКА: суффикс int32, ожидается int64
let big: int8 = 500;            // ОШИБКА: 500 не укладывается в int8
```

## 3. Правила типизации

- **Номинальная типизация:** два типа совместимы только если их имена
  совпадают.
- **Без неявных приведений:** любое преобразование — через оператор `as`.
- **Value semantics:** все значения (включая массивы и структуры)
  копируются при присваивании и передаче в функцию.

---

## 4. Составные типы

### 4.1 Структуры

```
struct Point {
    x: float64,
    y: float64,
}

let p: Point = Point { x: 1.0, y: 2.0 };
let px: float64 = p.x;
```

- Все поля обязаны быть инициализированы в литерале.
- Доступ через точку: `p.x`.
- Мутабельность полей следует из мутабельности переменной.
- Сравнение `==` и `!=` — поэлементное (все поля сравниваются рекурсивно).

### 4.2 Синонимы типов

```
type Meters = int32;
let distance: Meters = 100;  // полностью эквивалентно int32
```

Синоним не создаёт новый тип — это альтернативное имя для существующего.

### 4.3 Массивы

```
let arr: [int32; 5] = [1, 2, 3, 4, 5];
let first: int32 = arr[0];
```

- Размер является частью типа: `[int32; 5]` и `[int32; 10]` — разные типы.
- Индексация с нуля.
- Выход за границы — ошибка времени выполнения.
- Копируются целиком при присваивании и передаче в функцию.
- Массивы нулевого размера запрещены.

### 4.4 Пространства имён

```
namespace math {
    fn square(n: int32) -> int32 {
        return n * n;
    }
}

let s: int32 = math::square(5);
```

- Могут быть вложенными.
- Доступ через оператор `::`.

## 5. Строки

```
let s: string = "Hello";
let s2: string = s + ", world!";
let n: int32 = len(s2);
```

- UTF-8 кодировка.
- **Модель хранения:** указатель на байтовый буфер + длина в байтах (без
  завершающего нуля). Это позволяет хранить любые UTF-8
  последовательности и получать длину за O(1).
- `len(s)` возвращает длину в **байтах**, не в символах.
- Неизменяемы: после создания модифицировать нельзя.
- Value semantics: копируются при присваивании (копируется содержимое
  буфера, не только указатель).

---

## 6. Преобразования типов

- **Неявные преобразования отсутствуют.**
- **Явные (через `as`):**

```
let a: int32 = 10;
let b: int64 = a as int64;   // widening
let c: int8  = a as int8;    // narrowing (по модулю 2^8)
let f: float64 = a as float64;
let i: int32  = 3.7 as int32; // усечение к нулю → 3
```

- Разрешены между числовыми типами.
- `bool` → число: `true` → 1, `false` → 0.
- `char` ↔ `uint32`.
- Оператор `as` не определён для `string`, структур и массивов.

---

## 7. Поведение при переполнении

- Целочисленное переполнение — wrapping (по модулю 2ⁿ).
- Вещественное — по правилам IEEE-754 (NaN, ±inf).

---

## 8. Управление памятью

Ferrous использует арену на процесс: все динамические данные (буферы
строк, результаты конкатенации) выделяются в общем пуле и не
освобождаются до завершения программы. Это упрощает реализацию и
соответствует учебному характеру языка.

Стек используется для:
- локальных переменных (время жизни = блок),
- параметров функций,
- временных значений выражений.

Арена используется для:
- результатов конкатенации строк (`s1 + s2`).

Утечки памяти возможны: после завершения программы ОС освобождает арену
полностью. Внутри программы освобождения не происходит.
