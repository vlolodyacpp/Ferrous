# Генерация кода

Документ описывает подход к генерации кода компилятора Ferrous: выбор
платформы, маппинг типов в LLVM IR, представление составных типов,
соглашения о вызовах и runtime-библиотеку.

---

## 1. Выбор подхода

Ferrous компилируется в **LLVM IR** с последующей компиляцией в нативный
исполняемый файл через `clang++`. LLVM берёт на себя распределение
регистров, оптимизации и ABI целевой платформы. Для взаимодействия с
LLVM используется **LLVM C API** (`llvm-c/Core.h`) — это позволяет
избежать ABI-конфликта между libc++ (используется компилятором для
`import std;`) и libstdc++ (с которой собран системный LLVM).

## 2. Соглашения о вызовах

System V AMD64 ABI — наследуется от LLVM/clang. Компилятор не реализует
ABI вручную.

Все функции Ferrous транслируются в LLVM-функции с external linkage.
Имя в LLVM IR совпадает с именем в исходном коде для `main`; для
перегруженных функций добавляется суффикс по типам параметров.

## 3. Представление типов в LLVM IR

| Тип Ferrous | Тип LLVM IR |
|-------------|-------------|
| `void`      | `void` |
| `bool`      | `i1` |
| `int8`      | `i8` |
| `int16`     | `i16` |
| `int32`     | `i32` |
| `int64`     | `i64` |
| `uint8`     | `i8` |
| `uint16`    | `i16` |
| `uint32`    | `i32` |
| `uint64`    | `i64` |
| `float32`   | `float` |
| `float64`   | `double` |
| `char`      | `i32` (UTF-32 codepoint) |
| `string`    | `{ i8*, i64 }` (указатель + длина в байтах) |
| `[T; N]`    | `[N x <llvm_type_of_T>]` |
| `struct`    | именованный `%StructName = type { <fields> }` |

## 4. Представление строк

Строка — `{ ptr, len }`:
- `ptr` — указатель на UTF-8 байтовый буфер (без завершающего нуля);
- `len` — длина в байтах (`i64`).

Строковые литералы размещаются в глобальной read-only памяти LLVM
(константные массивы `[N x i8]`). При использовании в выражении
конструируется значение `{ ptr, len }` через `insertvalue`.

Конкатенация строк `s1 + s2` вызывает runtime-функцию
`__ferrous_str_concat`, которая выделяет память на арене и копирует оба
буфера.

## 5. Представление массивов

Массив `[T; N]` — встроенный LLVM-массив `[N x T]`. Размер фиксирован на
этапе компиляции. При передаче в функцию и присваивании копируется
целиком (value semantics).

Индексация `arr[i]` генерирует инструкцию `getelementptr` с последующей
загрузкой. Перед индексацией вставляется вызов `__ferrous_bounds_check`
для проверки границ во время выполнения.

## 6. Представление структур

Структура — именованный LLVM-тип `%StructName = type { ... }`. Поля
следуют в порядке объявления. Выравнивание определяется LLVM по правилам
целевой платформы.

Доступ к полю `obj.field` генерирует `getelementptr` с индексом поля
(порядковый номер в объявлении структуры).

## 7. Runtime-библиотека

Функции поддержки времени выполнения реализованы на C++ в файле
`rt/ferrous_rt.cpp`. Все точки входа объявлены как `extern "C"` для
прямой линковки с LLVM IR.

| Функция | Сигнатура | Назначение |
|---------|-----------|------------|
| `__ferrous_panic` | `(ptr, i64, i64)` | Аварийное завершение с сообщением |
| `__ferrous_assert_fail` | `(ptr, i64, i64)` | Провал assert |
| `__ferrous_div_check` | `(i64, i64) -> i64` | Проверка деления на ноль |
| `__ferrous_mod_check` | `(i64, i64) -> i64` | Проверка остатка на ноль |
| `__ferrous_bounds_check` | `(i64, i64, i64)` | Проверка границ массива |
| `__ferrous_print_int64` | `(i64)` | Вывод int64 |
| `__ferrous_print_float64` | `(double)` | Вывод float64 |
| `__ferrous_print_string` | `(ptr, i64)` | Вывод строки |
| `__ferrous_println_int64` | `(i64)` | Вывод int64 + \\n |
| `__ferrous_println_float64` | `(double)` | Вывод float64 + \\n |
| `__ferrous_println_string` | `(ptr, i64)` | Вывод строки + \\n |
| `__ferrous_input` | `() -> {ptr, i64}` | Чтение строки из stdin |
| `__ferrous_str_concat` | `(ptr, i64, ptr, i64) -> {ptr, i64}` | Конкатенация строк |
| `__ferrous_str_eq` | `(ptr, i64, ptr, i64) -> i8` | Сравнение строк |
| `__ferrous_int_to_str` | `(i64) -> {ptr, i64}` | int64 → string |
| `__ferrous_float_to_str` | `(double) -> {ptr, i64}` | float64 → string |

## 8. Pipeline компиляции

```
.fer → lex → parse → sema → LLVM IR → clang++ → executable
```

Кодоген (`src/codegen.cpp`) выполняет:
1. **Declare-фаза:** объявление runtime-функций, пользовательских
   структур и функций в модуле LLVM.
2. **Define-фаза:** генерация тел функций — обход аннотированного AST,
   рекурсивная трансляция выражений и инструкций в LLVM IR.
3. **Запись `.ll` файла** через `LLVMPrintModuleToFile`.
4. **Сборка исполняемого файла** вызовом `clang++` с линковкой
   runtime-библиотеки `ferrous_rt.cpp`.

## 9. Оптимизации

LLVM применяет стандартные проходы оптимизации на уровне `-O1`: constant
folding, dead code elimination, mem2reg — бесплатно. Собственный IR
(lowering в трёхадресный код) и дополнительные оптимизации не
реализованы в текущей версии.
