# Семантика языка Ferrous

Документ определяет семантику всех конструкций языка: структуру программы,
функции, переменные, выражения, управление потоком, область видимости,
встроенные функции и поведение при ошибках.

---

## 1. Общее описание

Ferrous — компилируемый язык программирования со статической
строгой номинальной типизацией. Сочетает простоту синтаксиса C с современными
возможностями Rust: иммутабельность по умолчанию, вывод типов для локальных
переменных, перегрузку функций. Предназначен для разработки приложений общего
назначения под платформу x86-64.

**Основные характеристики:**
- Статическая, строгая, номинальная типизация.
- Неявные **расширяющие** (widening) преобразования числовых типов во всех
  контекстах (инициализация, присваивание, `return`, аргументы, операнды
  операторов); **сужение** и **смена знака** — только явно через `as` (A.1.8).
- Value semantics: все значения передаются и присваиваются по значению.
- Иммутабельность переменных по умолчанию, мутабельность через `mut`.
- Вывод типов для локальных переменных из контекста инициализации.
- Перегрузка функций по числу и типам параметров.
- Модульная организация: функции, структуры, пространства имён.
- Расширение файлов исходного кода: `.fer`.

**Структура программы:**
- Каждый исходный файл `.fer` является отдельным модулем.
- На верхнем уровне модуля допускаются только объявления: функций, структур,
  синонимов типов, пространств имён.
- Выражения и инструкции допускаются только внутри тела функций.
- Программа обязана содержать ровно одну функцию `main` — точку входа.

## 2. Функции

### 2.1 Определение

```
fn function_name(param1: Type1, param2: Type2) -> ReturnType {
    /* тело функции */
}
```

Если функция не возвращает значения, указывается `-> void` или стрелка
опускается.

### 2.2 Вызов

```
let result: ReturnType = function_name(arg1, arg2);
```

### 2.3 Перегрузка

Функции могут иметь одинаковое имя при различии числа или типов параметров
(но не только типа возврата):

```
fn add(a: int32, b: int32) -> int32 { return a + b; }

fn add(a: float64, b: float64) -> float64 { return a + b; }

fn add(a: int32, b: int32, c: int32) -> int32 { return a + b + c; }
```

Разрешение перегрузки производится по **стоимостной модели**. Каждому
кандидату назначается суммарная стоимость приведения аргументов; побеждает
кандидат с наименьшей суммарной стоимостью. Если минимум достигается на
≥ 2 кандидатах — программа отклоняется с ошибкой `ambiguous call`.

Стоимость аргумента, тип которого **фиксирован** (имеет суффикс, явный тип
переменной или приведён через `as`), равна 0 при точном совпадении с типом
параметра. Допустимы также неявные приведения-расширения фиксированных типов
(целое→шире, `float32`→`float64`, целое→вещественное) с соответствующей
стоимостью. Это та же **единая** таблица неявных расширений, что действует
во всех контекстах языка (A.1.8) — полная таблица рангов в `types.md` §6.1.

Стоимость **нетипизированного** числового литерала зависит от типа параметра:

| Параметр | int-литерал | float-литерал |
|---|---|---|
| точное совпадение вида | 0 | 0 |
| `int32` | 1 | — |
| другой целый (`int8/16/64`, `uint*`) | 2 | — |
| `float64` | 3 | 3 |
| `float32` | 4 | 4 |

Нетипизированный float-литерал в целый параметр **не** приводится (кандидат
не подходит). Точное совпадение всех аргументов всегда побеждает любые
приведения литералов.

```
fn add(a: int32, b: int32) -> int32 { return a + b; }
fn add(a: int64, b: int64) -> int64 { return a + b; }

add(10, 20);           // OK: int32-версия (стоимость 1+1=2 < int64 2+2=4)
add(10i64, 20i64);     // OK: точное совпадение int64-версии (0)
add(10 as int32, 20);  // OK: первый аргумент фиксирует int32
```

### 2.4 Точка входа

Программа обязана содержать функцию `main`:

```
fn main() -> int32 {
    return 0;
}
```

Возвращаемое значение передаётся как код завершения процесса.

### 2.5 Семантика вызова

- Call-by-value: все аргументы копируются при передаче.
- Порядок вычисления аргументов — слева направо.

### 2.6 Параметры по умолчанию и именованные аргументы (A.2.9)

**Параметры по умолчанию.** Параметру можно задать значение по умолчанию:
`fn f(a: int32, b: int32 = 10)`. Правила:

- Параметры со значением по умолчанию обязаны идти **в хвосте** списка: после
  первого параметра с дефолтом все последующие тоже обязаны иметь дефолт.
  Нарушение — ошибка компиляции.
- Значение по умолчанию обязано быть **литералом** (целым, вещественным,
  булевым, строковым, символьным или унарным минусом над числовым литералом).
  Оно вычисляется и проверяется на соответствие типу параметра в момент
  объявления функции.
- При вызове недостающие хвостовые аргументы подставляются из значений по
  умолчанию.

**Именованные аргументы.** Аргумент можно передать по имени параметра:
`f(1, b=3)`. Правила:

- Позиционные аргументы идут **строго до** именованных. Позиционный аргумент
  после именованного — ошибка компиляции.
- Имя именованного аргумента обязано совпадать с именем параметра выбираемой
  функции; неизвестное имя — ошибка.
- Один параметр не может быть задан дважды (позиционно и по имени, либо двумя
  именованными аргументами) — ошибка.
- Именованные аргументы позволяют переставлять хвостовые параметры:
  `box(h=3, w=2)`.

**Порядок вычисления.** Аргументы вычисляются **в порядке параметров**
(а не в порядке записи в вызове); значения по умолчанию вычисляются на месте
своих параметров.

**Взаимодействие с перегрузкой.** Кандидат-перегрузка участвует в разрешении,
если после раскладки позиционных и именованных аргументов по параметрам все
оставшиеся (незаданные) параметры имеют значения по умолчанию. Раскладка
строится отдельно для каждого кандидата (имена параметров у перегрузок могут
различаться), затем применяется обычная стоимостная модель (§2.3); слоты,
заполненные значениями по умолчанию, считаются точным совпадением (стоимость 0).

```
fn pick(x: int32) -> int32 { return 100 + x; }
fn pick(x: int32, y: int32 = 5) -> int32 { return x + y; }

pick(1);        // → pick(int32): точная сигнатура без дефолта побеждает (101)
pick(1, 2);     // → pick(int32, int32): 3
```

Именованные аргументы и значения по умолчанию поддерживаются только для
пользовательских функций (встроенные `print`/`len`/… вызываются позиционно).

## 3. Переменные и мутабельность

### 3.1 Объявление

```
let x: int32 = 10;        // иммутабельная
let mut y: int32 = 20;    // мутабельная
let z = 3.14;             // тип выведен как float64
```

### 3.2 Правила

- Переменная обязана быть инициализирована при объявлении.
- Повторное присваивание иммутабельной переменной — ошибка компиляции.
- Shadowing разрешён: внутреннее объявление перекрывает внешнее.
- Двойное объявление в одной области видимости — ошибка.

### 3.3 Вывод типов

Если тип в `let` опущен, он выводится из выражения справа:

```
let x = 10;               // int32
let y = 3.14;             // float64
let s = "hello";          // string
let arr = [1, 2, 3];      // [int32; 3]
```

Вывод только локальный: параметры функций и возвращаемые типы указываются
явно.

## 4. Выражения и операторы

### 4.1 Виды выражений

Язык поддерживает следующие виды выражений:

- **Литералы:** целые, вещественные, булевы, строковые, символьные.
- **Литералы массива:** `[1, 2, 3]` — все элементы должны иметь одинаковый тип.
- **Литералы структуры:** `Point { x: 1.0, y: 2.0 }` — все поля обязаны быть
  инициализированы.
- **Имена:** простые (`x`) и квалифицированные (`math::square`).
- **Унарные:** `-x` (арифметическое отрицание), `!x` (логическое отрицание),
  `~x` (побитовое отрицание).
- **Арифметические:** `+`, `-`, `*`, `/`, `%`.
- **Битовые:** `&`, `|`, `^` (И/ИЛИ/исключающее ИЛИ), `<<`, `>>` (сдвиги).
- **Сравнения:** `==`, `!=`, `<`, `<=`, `>`, `>=`.
- **Логические:** `&&`, `||`, `!`.
- **Приведение типа:** `expr as Type` (постфиксный приоритет).
- **Вызов функции:** `f(arg1, arg2)`.
- **Индексирование массива:** `arr[i]` — `i` должен иметь целочисленный тип.
- **Доступ к полю структуры:** `p.x`.
- **Доступ к элементу пространства имён:** `math::square`.
- **Скобки для группировки:** `(expr)`.

### 4.2 Приоритет и ассоциативность

Чем меньше номер — тем крепче связывает (`1` — наивысший приоритет).

| Приоритет | Операторы                   | Ассоциативность |
| --------- | --------------------------- | --------------- |
| 1         | `()` `[]` `.` `::` `as`     | слева-направо   |
| 2         | унарные `-` `!` `~`         | справа-налево   |
| 3         | `* / %`                     | слева-направо   |
| 4         | `+ -`                       | слева-направо   |
| 5         | `<< >>`                     | слева-направо   |
| 6         | `< <= > >=`                 | слева-направо   |
| 7         | `== !=`                     | слева-направо   |
| 8         | `&`                         | слева-направо   |
| 9         | `^`                         | слева-направо   |
| 10        | `\|`                        | слева-направо   |
| 11        | `&&`                        | слева-направо   |
| 12        | `\|\|`                      | слева-направо   |
| 13        | `=` и составные `+= -= *= /= %= &= \|= ^= <<= >>=` | справа-налево |

`as` относится к постфиксному слою и связывает крепче унарного минуса:
`-x as int32` означает `-(x as int32)`.

### 4.3 Семантика операторов

- **Унарный `-`** определён для всех числовых типов. Для беззнаковых целых —
  отрицание по модулю 2ⁿ (wrap), как и в остальной беззнаковой арифметике.
- **Унарный `!`** определён только для `bool`.
- **Унарный `~`** (побитовое НЕ) определён только для целых типов.
- **Арифметические `+ - * / %`** требуют числовых операндов. Если их типы
  различаются, узкий операнд неявно **расширяется** до общего типа (A.1.8);
  результат — общий тип. Несовместимые типы (разная знаковость, float→int) —
  ошибка (нужен `as`). Операция `+` разрешена для строк в виде конкатенации.
- **Битовые `& | ^`** определены только для целых типов; операнды приводятся
  к общему типу (A.1.8), результат — общий тип.
- **Сдвиги `<< >>`** определены только для целых. Величина сдвига берётся
  **по модулю ширины типа** (`amt & (w − 1)`), поэтому сдвиг на величину
  ≥ ширины и отрицательную величину знакового типа определён (после маски).
  `>>` — арифметический для знаковых, логический для беззнаковых.
  Полное описание битовых операторов и поведения нештатных величин сдвига —
  в отдельном документе `bitwise.md`.
- **Операторы сравнения `< <= > >=`** определены для числовых типов,
  результат — `bool`. Для беззнаковых используется беззнаковое сравнение.
- **`== !=`** определены для всех встроенных типов, массивов и структур
  (поэлементное сравнение); результат — `bool`.
- **`&& ||`** определены только для `bool`, используют short-circuit (ленивую
  оценку): правый операнд не вычисляется, если результат определён левым.
- Деление целых — усечение к нулю (`-7 / 2 == -3`). Беззнаковое деление и
  остаток — беззнаковые.
- Деление на ноль и остаток по нулю (для целых) — ошибка времени выполнения.

### 4.3.1 Составные присваивания (A.1.9)

Составной оператор `a op= b` (`+= -= *= /= %= &= |= ^= <<= >>=`)
эквивалентен `a = a op b` со следующими уточнениями:

- **Адрес `a` вычисляется ровно один раз.** Для `arr[i()] += 1` функция `i()`
  вызывается единожды (это поведение наблюдаемо при наличии побочных эффектов).
- Левая часть `a` обязана быть мутабельным lvalue (те же проверки, что и у
  обычного присваивания): иначе — ошибка компиляции
  («left-hand side of assignment must be an lvalue» / «cannot assign to
  immutable variable»).
- К операндам применяются правила соответствующей бинарной операции `op`:
  `+= -= *= /=` — для числовых типов; `%=` — только для целых; `&= |= ^=`
  и сдвиги `<<= >>=` — только для целых. `+=` для строк выполняет
  конкатенацию.
- Правый операнд `b` неявно **расширяется** до типа `a` по общей таблице
  (A.1.8), как у `=`; сужение/смена знака — ошибка (нужен `as`). Исключение —
  сдвиги `<<= >>=`, где величина сдвига может быть любого целого типа.
  Тип результата — всегда тип `a`.
- Нетипизированный целочисленный литерал справа подстраивается под тип `a`
  (`let mut x: int8 = 1; x += 2;` — корректно).

### 4.4 Порядок вычисления

- Операнды бинарных операторов вычисляются **слева направо**.
- Аргументы функций вычисляются **слева направо**.
- Индекс массива `arr[i]` — сначала вычисляется `arr`, затем `i`.
- Исключение: операторы `&&` и `||` используют ленивую оценку (правый операнд
  может не вычисляться).

### 4.5 Строковые операции

- Конкатенация: `s1 + s2`
- Длина: встроенная функция `len(s)` → `int32` (в байтах после декодирования escape)
- Сравнение: `==`, `!=`
- Escape-последовательности: `\n \t \r \\ \' \" \0` (см. grammar.md, `escape_seq`).
  Неизвестный escape — ошибка компиляции. Строковый литерал не может
  содержать сырой перевод строки; используйте `\n`.

## 5. Управляющие конструкции

### 5.1 Условный оператор

```
if condition {
    // ...
} else if other_condition {
    // ...
} else {
    // ...
}
```

Условие обязано иметь тип `bool` — никаких «truthy» значений.

### 5.2 Циклы

```
while condition {
    // ...
}
```

Цикл `while` — единственная базовая конструкция цикла.

### 5.3 Прерывания

- `break` — немедленный выход из ближайшего цикла.
- `continue` — переход к следующей итерации.
- `return expr;` — возврат значения из функции.
- `return;` — возврат из функции с типом `void`.

Все пути функции с ненулевым типом возврата обязаны завершаться `return`.

### 5.4 Блок и нулевая инструкция

- Блок `{ ... }` вводит новую область видимости.
- Нулевая инструкция `;` не производит эффекта.

---

## 6. Область видимости и разрешение имён

- Лексическая (статическая) область видимости.
- Идентификатор разрешается в ближайшей охватывающей области.
- Shadowing разрешён, двойное объявление в одной области — ошибка.
- Использование до объявления не допускается (кроме функций и типов верхнего
  уровня, видимых во всём файле).
- Переменная существует от точки объявления до конца блока.

## 7. Встроенные функции

| Функция   | Сигнатура                       | Назначение                            |
| --------- | ------------------------------- | ------------------------------------- |
| `print`   | перегружена, см. §7.1           | Вывод значения в stdout               |
| `println` | перегружена, см. §7.1           | Вывод значения в stdout с `\n` в конце|
| `input`   | `fn input() -> string`          | Чтение строки из stdin                |
| `len`     | `fn len(s: string) -> int32`; `fn len(a: [T; N]) -> int32` | Длина строки в байтах / число элементов массива (статически из типа) |
| `exit`    | `fn exit(code: int32) -> void`  | Завершение с кодом возврата           |
| `panic`   | `fn panic(msg: string) -> void` | Аварийное завершение с сообщением     |
| `assert`  | перегружена, см. §7.1           | Проверка условия и аварийное завершение |
| `to_string` | `fn to_string(x: T) -> string` для всех числовых и `bool` | Преобразование числа/булева в строку |
| `to_int`  | `fn to_int(s: string) -> int64` | Разбор целого из строки; при ошибке разбора возвращает 0 |
| `to_float`| `fn to_float(s: string) -> float64` | Разбор вещественного из строки; при ошибке — 0.0 |

### 7.1 Перегрузки `print`, `println` и `assert`

Функции `print` и `println` перегружены для всех встроенных примитивных
типов. Для каждого из приведённых ниже типов существует по одной перегрузке
`print(x: T) -> void` и `println(x: T) -> void`:

- строковый: `string`
- булев: `bool` (выводится как `true` / `false`)
- символьный: `char`
- знаковые целые: `int8`, `int16`, `int32`, `int64` (десятичная запись со знаком)
- беззнаковые целые: `uint8`, `uint16`, `uint32`, `uint64` (десятичная запись
  без знака)
- вещественные: `float32`, `float64` (десятичная запись; специальные
  значения — `nan`, `inf`, `-inf`)


Функция `assert` имеет две перегрузки:

```
fn assert(cond: bool) -> void
fn assert(cond: bool, msg: string) -> void
```

При `cond == false` программа завершается с сообщением:
- без `msg`: `runtime error: assertion failed at line N`
- с `msg`: `runtime error: assertion failed: <msg> at line N`

**Составные типы** (структуры, массивы) **не поддерживаются** в `print`/
`println`: их поля/элементы нужно выводить по отдельности либо
предварительно преобразовывать в `string`.

**Разрешение перегрузки с литералами.** По стоимостной модели §2.3
нетипизированный int-литерал предпочитает перегрузку `int32` (стоимость 1),
а float-литерал — `float64` (стоимость 3). Поэтому вызов с одним
нетипизированным литералом однозначен:

```
print(42);            // OK: печатается как int32
print(42i32);         // OK: суффикс фиксирует int32
print(42 as int32);   // OK: явное приведение фиксирует int32
print(3.14);          // OK: печатается как float64
print(3.14f32);       // OK: суффикс фиксирует float32
print("hello");       // OK: строковый литерал однозначно string
print(true);          // OK: булев литерал однозначно bool

let x: int32 = 10;
print(x);             // OK: x имеет фиксированный тип int32
```

Если нужно вывести сразу несколько значений, делается последовательность
вызовов:

```
print("sum = "); println(sum);
```

## 8. Ошибки времени выполнения

При возникновении ошибки программа завершается с сообщением вида:

```
runtime error: <сообщение> at line <N>
```

и ненулевым кодом возврата (по умолчанию 1).

Обязательно обрабатываемые ошибки:

| Ситуация                      | Сообщение                                          |
| ----------------------------- | -------------------------------------------------- |
| Деление на ноль               | `runtime error: division by zero at line N`        |
| Остаток от деления на ноль    | `runtime error: modulo by zero at line N`          |
| Выход за границы массива      | `runtime error: index out of bounds at line N`     |
| Вызов `panic(msg)`            | `runtime error: <msg> at line N`                   |
| Провал `assert(cond)`         | `runtime error: assertion failed at line N`        |
| Провал `assert(cond, msg)`    | `runtime error: assertion failed: <msg> at line N` |

Сообщения выводятся в стандартный поток ошибок (`stderr`). Номер строки
соответствует позиции операции в исходном коде.
